# Rust engine workspace

This is the Rust port of Forge's Java rules engine. Read the root `/AGENTS.md` first, plus `docs/agents/PARITY_PHILOSOPHY.md`. Most parity work bottoms out here.

## Required reading: the DSL spec

Card scripts are the source of truth for behavior; the engine evaluates them. Before any work that touches abilities, triggers, replacements, static abilities, costs, the stack, SVars, selectors, or layered effects, read:

- **`docs/forge-dsl-semantics.md`** — runtime model: execution pipeline, stack semantics, targeting, cost payment, layer system, SVar resolution, determinism invariants, known CR deviations.
- **`docs/forge-dsl-grammar.md`** — syntax / parsing model. Read this when working on the parser, the IR, or interpreting an unfamiliar param.

When you write or change engine logic, write IRs and resolution code that mirror the semantics in the spec exactly. If your implementation diverges from the spec, either the implementation is wrong or the spec needs updating — don't silently drift.

## Conventions

- **Mirror Java exactly.** See `docs/agents/PARITY_PHILOSOPHY.md`.
- **One Forge concept per file.** New effects, triggers, replacements, statics, keywords each get their own file named after the Java class, registered in their module's `mod.rs`.
- **`Game` owns everything.** All mutation flows through `&mut Game`. No interior mutability, no shared references.
- **`GameState::cards` holds `Arc<Card>`, so a snapshot shares every card and a card is copied on its first write after one.** `GameSnapshot::capture` runs before every spell cast and every activated ability's cost payment, and it clones the vector of pointers, not the cards. Write through `card_mut`, or `Arc::make_mut` in a loop over `cards`. A loop that writes every card copies all of them while a snapshot is alive, so test each card first and write only the ones that change, as the layer pass's reset does with `static_layer_reset_is_noop` and the turn resets with `Card::global_turn_state_is_clear` and `Card::turn_tracking_is_clear`.
- **Engine hash collections use the fixed-hasher aliases.** `crate::HashMap` and `crate::HashSet` (`manabrew-engine/src/lib.rs`) wrap the std collections with `DefaultHasher`, so iteration order is the same on every run of the same seed. `manabrew-engine/clippy.toml` rejects `std::collections::HashMap`, `HashSet`, `RandomState`, and `rand::thread_rng`. Where iteration order reaches game logic, use `IndexMap`/`IndexSet`.
- **Crate-wide `#![allow(...)]`s in `lib.rs` are intentional.** They document parity trade-offs.
- **A trigger pushed onto a built card must raise `base_trigger_count`.** The layer reset in `staticability/layer.rs` truncates `card.triggers` to `base_trigger_count + pump_trigger_count` on every pass, so a trigger added to an effect card after construction vanishes on the first zone move unless the count covers it. `effect_effect.rs` and `player/player_factory_util.rs::add_trigger` both set it; do the same in any new code that builds an effect card.
- **A keyword that changes a card's types does it inline in the layer pass, not through a generated static.** `keyword_gen.rs` makes triggers and abilities but no static abilities, and `StaticAbility::remove_type` is parsed from `RemoveType$` and then never read, so a `RemoveType$` written into a card script is silently a no-op. Keyword-derived type and restriction changes live in the "Keyword-derived restrictions" block of `staticability/layer.rs` (Unleash's can't-block, Impending's `RemoveType$ Creature`), which runs after the per-pass reset so it recomputes every pass and reverts on its own. Anything there that drops a card type must call `sanitize_subtypes` itself, as the `type_changed` loop at the end of the pass does — that loop only covers targets the static effects touched, so an inline change skips it and leaves creature subtypes on a card that is no longer a creature.
- **A trait on a card face carries that face's `CardState`, and the other part's traits need it too.** Java's `CardTraitBase.getCardStateName` returns the state the trait was defined on, and `TriggerUnlockDoor.performTest` compares it against the unlocked door with no null guard — so a `ThisDoor$ True` trigger always knows its face. In this port `card_assembly::mark_triggers_card_state` marks the front card's copy of both faces' triggers, but `Card::transform` swaps in `other_part.triggers`, a separately parsed list. Those have to be marked at assembly as well, or after a Room is cast as its right half its `ThisDoor$` trigger has no state, the face check is skipped, and it fires for both doors. Anything else read off a trait's `CardState` needs marking in both places.
- **A Room keeps both doors' triggers on the card and filters them by which doors are open.** Java moves `currentState` and registers that state's traits (`Card.updateRooms`); this port has no per-state trait lists at runtime, so `card_assembly` puts both faces' triggers on the front card with their `CardStateName` and `TriggerHandler::register_one_trigger` skips one whose `LeftSplit`/`RightSplit` door is still locked (`Card::room_door_locked`, backed by the `UnlockedDoors` SVar). `Card::transform` therefore restores the combined trigger list for a Room after its swap, next to the `UnlockedDoors`/`UnlockedRoomCount` SVars and the unlock abilities it already carries across — casting a Room as its right half would otherwise leave the left door's triggers on `other_part`, where no later unlock can reach them, and a card like Defiled Crypt would never fire its half once opened. Static abilities and replacement effects still swap, because nothing filters those by door; a Room whose locked half carries one needs that filter written first.
- **An `ST$` ability resolves where it is played and never reaches the stack.** Java's `MagicStack.add` (`MagicStack.java:327`) calls `AbilityUtils.resolve(sp)` and returns for an `AbilityStatic`, before it can become a stack entry. The port mirrors this case by case in `GameLoop::play_spell_ability`, which routes Plot, `Mode$ TurnFaceUp` and a Room's unlock to `resolve_immediate_ability`; a new `ST$` API needs the same routing or it buys its controller a priority round Forge never grants, which shows up as `PASS_STATE` rather than a state divergence. The Room unlock is synthesised as `AB$ UnlockDoor` in `card_assembly.rs` where `CardFactoryUtil.abilityUnlockRoom` writes `ST$`, so the test is `ActivatedAbility::is_unlock_door`, not the prefix. Java's second half of that branch, a trigger whose overriding ability is an `AbilityStatic`, is not ported.
- **A face-down permanent has a face-down state.** `Card::set_original_state_as_face_down` (Forge: `setOriginalStateAsFaceDown` + `CardUtil.getFaceDownCharacteristic`) saves the printed characteristics in `face_down_state` and leaves a colourless 2/2 `Creature` with no cost and no abilities; `turn_face_up` restores them, and every path that turns a card up or moves it between zones goes through `turn_face_up`. `card_name` is kept, so name lookups still work; the parity snapshot and `FmtCtx::card` blank it, and a seat's view sends it only to a player `game_view_dto::can_face_down_be_shown_to` lets see the face. Game-log text goes to every seat, so it names a face-down card by `Card::log_name`, `FACE_DOWN_LOG_NAME` (Forge's log prints `CardView.toString`, "Face-down card (H<id>)"); turning a morph face up still logs its name, since that special action reveals it. The face-down cast (Morph, Megamorph, Disguise) applies it before the permanent enters, as `abilityCastFaceDown.resolve` does, so enters-the-battlefield replacements see the face-down card. The action space prices that cast on a face-down copy of the card (`playability::can_pay_face_down_cast`), as `CostAdjustment.adjust` turns the host face down before it reads the cost statics: `ValidSpell$ Spell.isCastFaceDown` (Obscuring Aether, Dream Chisel) and a `ValidCard$ Creature` static adjust the {3} or a `MayPlayAltManaCost$`, and a static keyed on the printed colour or types does not. `CantBeCast` is asked twice, as Forge does: the action space asks it of the card as it sits in hand, face up (the harness's `ActionSpace.spellHost` is an LKI copy of the hand card), for the land and `MayPlay$` face-down options as well; the cast asks it again of the face-down card on the stack (`checkRestrictions` after `moveToStack`), so a face-down cast under Void Winnower is offered and then rolled back. That second check runs for every spell, and its `OnlySorcerySpeed` test ignores the pending cast's own stack entry, since Java's `MagicStack` gets the spell only at `add`. Java's `GameActionUtil.rollbackAbility` leaves `Card.facedown` set on the card it puts back in hand after a failed face-down cast; Forge's `PlaySpellAbility.playSpellAbility` clears it afterwards, but the harness calls `rollbackAbility` directly. Every later LKI copy of that card is then face down (`CardCopyService.getLKICopy`): no name, a `Creature` of mana value 0 with no abilities, keeping its face-up colour and power and toughness, so each later `CantBeCast` check on it sees mana value 0, and `CostAdjustment` prices a later face-down cast on the face-up card because the host already reads as face down. Rust mirrors this only when `GameState::mirror_forge_bugs` is set, which the parity runner does and the engine default does not: the cast rollback sets `Card::stale_face_down` on the hand card, `static_ability_cant_be_cast::restriction_host` asks `CantBeCast` of the face-down view, and `playability::can_pay_face_down_cast` prices the face-up card. Any zone move clears it, as Java's `copyCard` does not copy `facedown`; Java keeps it on a move to the battlefield, which is not mirrored. Manifest, Manifest Dread and Cloak apply it before the card moves, as `Card.manifest` and `Card.cloak` do; Cloak's Ward:2 is an intrinsic keyword of the face-down state, not a pump keyword that cleanup removes. A `FaceDown$` ChangeZone, ChangeZoneAll or Dig applies it before the move as well, through `card_factory_util::turn_face_down_with_state` (Java `turnFaceDown(true)`: the state and the Morph or Disguise turn-up ability) and `set_face_down_state` (`CardFactoryUtil.setFaceDownState`: `FaceDownPower$`, `FaceDownToughness$`, `FaceDownSetType$`); MakeCard's `FaceDown$` calls the first alone, as `MakeCardEffect.finishMaking` does. A manifested or cloaked creature card gets a `Mode$ TurnFaceUp | ManifestUp$ True` (or `CloakUp$`) ability for its mana cost from `card_factory_util::ability_turn_face_up` (Forge: `CardState.getManifestUp`), pushed before the move as the morph cast pushes its own; cost reductions for turning face up (`ValidSpell$ Static.isTurnFaceUp`) are not applied yet. Turning face up restores the card first and runs the `TurnFaceUp` replacement after, behind a `cant_happen_check` (Forge: `Card.turnFaceUp`), and its `ReplaceWith$` ability runs through `replace_moved::execute_replace_with`. A `Duration$ UntilFacedown` (Vesuvan Shapeshifter's copy) goes on `GameState::facedown_commands` for its host (Java `addFacedownCommand`). `SetState`'s `TurnFaceDown` runs them before it captures the face-down state, which is taken from the current characteristics, so an unclone run after it would overwrite the 2/2; a host's commands are dropped when it leaves the battlefield, as Java's belong to the old object.
- **A may-look grant lives on the card and dies with it.** `Card::may_player_look` (Forge `Card.mayPlayerLook`) answers from `may_look_face_down_exile` (Forge `addMayLookFaceDownExile`: a `WithMayLook$` Dig or ChangeZone, a `Foretold$` ChangeZone, the Foretell action, Heist) and the keyed `may_look` list (`addMayLookAt`). The layer pass fills `may_look` from `MayLookAt$` statics under the static's layer id (`EffectKind::MayLookAt`, Java's RULES layer) and drops those entries at the top of every pass, as `StaticEffect.remove` calls `removeMayLookAt`; a grant on a face-down exiled card also joins `may_look_face_down_exile`, which outlives the static, as in Java. `move_card_internal` clears both where Java's `changeZone` copies the card. Seat views read it through `game_view_dto::can_be_shown_to` and `can_face_down_be_shown_to`. It changes no game state, so a parity run cannot see it. Not ported: the `topLibsCast` exception for a library top card during a cast, and the hidden agenda grant.
- **A token's edition follows `TokenInfo.getProtoType`, and its art pick draws from the game RNG.** `EffectContext::sync_token_art_rng` starts from the ability's original host (else its host), follows `TokenFallbackCode`, and pins the script's edition for the rest of the game (`GameState::token_edition_pins`). An edition without the token falls back to the first edition, in code order, that has it (`TokenDb.getTokenFromEditions`); more than one art variant draws `nextInt(variants)`. The token takes that edition as its set code and an effect card takes its host's, as in Forge; other cards made during the game have no set code and go straight to the fallback.
- **A trigger's player filter goes through `player_property::is_valid`** (Java `Player.isValid`), from `Trigger::matches_optional_valid_player_filter`. The compiled-selector player matcher in `valid_filter.rs` has no game, so it cannot answer `Active`, `NonActive` or any other property that needs one and counts them as matches. `valid_filter::matches_valid_player_selector_in_game` keeps that fast path for a filter it can answer (`You`, `Opponent`, `Player`) and sends any other to `player_property::is_valid`; the `Caster$` of `CastWithFlash`, `ValidPlayer$` of `CantDraw`, `ValidActivator$` and `ValidTarget$` of Panharmonicon and `DisableTriggers`, `ValidTarget$` of `InfectDamage`, the player `Target$` of `CantAttack` and a `ConditionPresent$` player use it, so Unstable Glyphbridge's `Target$ Player.IsRemembered` no longer names every player. The callers with no game still count those properties as matches: `CardTraitBase::matches_valid_with_player`, the card-slice statics (`CantPutCounter`, `BlockRestrict`, `IgnoreHexproof`), the attack and block costs, and the `Untap` and `AddCounter` replacements. A spell-cast trigger reads the caster from `RunParams::activator`, which every `SpellCast` emitter sets, as `MagicStack.add` puts `AbilityKey.Activator`.
- **A static's `GainControl$` hands the card back when the static stops applying.** Java adds a temp controller under the static's timestamp and `StaticEffect.remove` drops it; here the `SetController` arm records the controller it took the card from (`Card::static_control_base`), and the layer pass changes the controller back for every card no static gave control to this pass. Before this, bouncing Kitnap left its creature with Kitnap's controller for good. A zone change clears the record with the temp controllers. Inside the pass a control change only moves the card's controller and zone lists (`GameState::set_temp_controller`), as Java's temp controllers change `getController` at once; the end of the pass compares every card with its controller at the start and runs the rest of Java's `controllerChangeZoneCorrection` (the change-controller commands, summoning sickness and, during combat, removal from combat) once per net change. `GameState::change_controller`, which effects use, is the same two steps. The combat lives on `GameLoop`, so the correction queues the card in `GameState::pending_remove_from_combat` and the priority loop removes it after each state-based check; an attacker given to the defending player otherwise kept attacking (Stiltzkin, Moogle Merchant). Calling `change_controller` for each `SetController` made a creature under two control statics (Confiscate on a Confiscated Memnite) change hands twice a pass and stay summoning sick.
- **A static ability only applies when its conditions hold, so every reader goes through `staticability/`.** `StaticAbility::check_mode` answers the mode alone; `check_conditions_full` is the port of Java's `StaticAbility.checkConditions` and is what gates `Condition$`, `CheckSVar$`/`SVarCompare$`, `Phases$`, `PlayerTurn$`, the host's zone and `phased_out`. A combat or playability path that matches a static itself — mode plus `ValidX$` — applies it unconditionally, and a card that is only sometimes unblockable is then always unblockable. `combat_util::can_creature_block` had such a copy of `CantBlockBy` and now calls `static_ability_cant_attack_block::cant_block_by`. A `CantAttack` static is answered per attacker and defender by `static_ability_cant_attack_block::cant_attack` (Java `CombatUtil.canAttack(attacker, defender)`), from `combat_util::get_available_attackers`, `can_attack_defender` and `can_attack_next_turn`; the layer pass used to fold it into a per-card flag over the static's `ValidCard$` set, which could not read `Target$` (The Aetherspark forbids attacking only itself). The Defender keyword is answered in `cant_attack` too, since Java makes it a `CantAttack` static whose one exception is a `CanAttackDefender` static (`applyCantAttackAbility`); `combat_util::can_attack_defender` consults `CanAttackDefender` nowhere else, and requiring one for every player defender kept any creature from attacking a player whose opponent controlled a planeswalker. `CantBlock` still goes through the layer pass's `cant_block_static` flag, which is equivalent because Java's `cantBlock` has no defender dimension. Read the `static_ability_*.rs` function before writing a match loop; if one exists, call it. The parity agent (`deterministic_agent.rs`) has its own copies of several of these against the snapshot game, so a fix here can measure zero until the agent's copy is fixed too. Its `choose_attackers` draws each attacker's defender from the flat `get_possible_defenders` list, where Java's `DeterministicController` draws from that attacker's `CombatUtil.canAttack` list, so parity never observes `can_attack_defender`.

- **One card's simultaneous triggers follow Forge's trigger ids, and those depend on how the card object was built.** The parity harness orders them by host timestamp and then trigger id. On every zone change `CardCopyService.copyCard` rebuilds a card that has a paper card from its script: `T:` triggers first, keyword triggers after. A keyword trigger (Evoke's sacrifice) therefore has the higher id, is pushed after the card's own enters triggers and resolves first. A token or a copied permanent goes through `copyStats` (`CardState.copyFrom`), which copies the keywords first. `register_evoke_sacrifice_triggers` sets `DelayedTrigger::sort_after_active` from that rule; a new keyword trigger modelled as a delayed trigger needs the same decision. Runtime trigger ids come from one `TriggerHandler` counter that starts at 50000, as Java's `Trigger.maxId` does, above the per-card ids a script's triggers get: delayed and immediate triggers take theirs when registered and a Clone's copied triggers when copied (`TriggerHandler::next_trigger_id`). A delayed trigger that an ability created (`DelayedTrigger::spawning_ability`) and an immediate trigger sort among the host's own triggers by that id, so Earthbend's return goes above Bumi, Unleashed's untap-all, and a Superior Spider-Man whose Mind Swap chain ends on Deceit orders Deceit's enters triggers between the exile triggers made before and after the copy. A player's effect cards (speed, the monarch, the initiative, City's Blessing, radiation, An Enduring Story) enter the command zone without a timestamp (`add_player_effect_card`), as Forge's `PlayerZone.add` gives them none, so their triggers sort before that player's other simultaneous triggers. A delayed Phase trigger needs no same-step guard: `emit_phase_trigger` queues the step's Phase event and the step's first `process_triggers` matches it before anything in the step resolves, so a delayed trigger made later in the step waits for the next Phase event, which is an extra step of the same turn when one follows (Wiccan, Rising Magician's return in Y'shtola Rhul's additional end step), as Java's `onPhaseBegin` runs the Phase trigger at the step's start. A delayed trigger sorts by the timestamp its host object had when it was registered (`DelayedTrigger::source_timestamp`), as Java's `DelayedTriggerEffect` hosts it on the ability's host card and `registerDelayedTrigger` on an LKI copy of it; a Phase delayed trigger registered without one sorts at 0, before every host, so a new registration site sets it (Kykar, Zephyr Awakener's and Niko, Light of Hope's end step returns). Each player's batch is ordered when that player's APNAP turn comes, as `MagicStack.chooseOrderOfSimultaneousStackEntry` collects it then: `process_triggers` sorts the triggers matched while earlier players' went on the stack into the non-active player's pending ones (`TriggerHandler::order_simultaneous_triggers`), so a Ward raised by the active player's targeting trigger goes between its host's triggers and a newer permanent's, not on top.
- **Every `PlayerAgent` decision gets the live game at the call.** A decision method that does not take `&GameState` takes a `DecisionContext` (the game and the mana pools) right after `&mut self`, and `choose_action` takes a `PriorityContext`: it owns the priority window's `&mut GameState` borrow, `action_space()` re-applies static abilities and builds the action space, and `context()` lends the game out. The reason is timing: a prompt raised during resolution or payment gets no `snapshot_state` of its own, so an agent that answers from its last snapshot sees the resolving spell still on the stack and the sacrificed Treasure still in play, where Forge's controllers read the live game. A call site passes what it holds: effects `DecisionContext::new(ctx.game, ctx.mana_pools)`, `GameLoop` methods `&self.mana_pools`, `PlayerController` its own pools, the replacement handler its `ReplacementRuntime`'s. A caller that holds no pools passes `DecisionContext::game_only`: `GameState` methods (the legend rule, a state-based-action confirm, an indirect aura attach, `move_card`'s number choice, the enters-tapped replacement prompt they reach) and `get_new_chooser`. The replacement handler passes its `ReplacementRuntime`'s pools when it has one. The decision methods that take `&GameState` instead of a context carry no pools either. `PromptAgent` answers those with the pools of its last `snapshot_state`, which it copies each time. `notify` gets a context as well, because a seat's state emits and its turn, card-played and snapshot notices read the game. The auto-payer's decision callbacks (`ManaPayCallback::ChooseSacrifice`, `ChooseColor`, the `Confirm*` variants and the rest) carry `&GameState` for the same reason, because the payer holds the `&mut` borrow. The context lives only for the call; an agent must not keep it. Parity's `CapturingAgent` forwards it to the inner agent without logging it (the context arms of `parity_agent_callback!`), so the traces do not change.
- **Auto in an interactive payment floats mana, as the Forge host's `AutoPay.floatManaForCost` does.** `PlayerAgent::auto_pay_floats_mana` is true only for `PromptAgent` (app seats and the SimpleAi bot). - **A turn can be resumed from a checkpoint taken at its start.** With a sink set (`GameLoop::set_turn_checkpoint_sink`, off by default and one `Option` test per turn when off), `begin_turn` hands it a `TurnCheckpoint` after `log_turn_begin` and before any agent's `snapshot_state`, together with the agents, so the host can capture their state at the same point. The checkpoint holds the `GameSnapshot` (game, pools, combat, trigger handler, stack), the game RNG through `GameRng::checkpoint_state` (`None` for an RNG that does not implement it, which a resume then leaves where it is), and every `GameLoop` field the loop reads later: `previous_game_state`, `next_checkpoint_id`, the reserved-sacrifice and source-reuse stacks, the mana-undo stacks and flag. It leaves out the UI rewind history (`checkpoints`), which only a `take_restore_request` reads, and the configuration the caller sets on the `GameLoop` it resumes on (token data, abort signal, action-space mode). `GameLoop::resume` / `GameRuntime::resume` restore it and run the rest of that turn from `continue_turn` (the `snapshot_state`, `SnapshotCreated` and `TurnChanged` calls onward), then the usual turn loop, with the agents the caller passes. - **An ability that runs inside a Moved replacement gets the game runtime.** `move_card_internal` takes the `ReplacementRuntime`, so a `ReplaceWith$` chain on a permanent entering the battlefield (an enters-as-a-copy Clone, its `ImmediateTrigger`) registers delayed triggers on the real `TriggerHandler` and draws from the game RNG. - **A `SpellCast` trigger with `TargetsValid$` only sees spells that target a matching entity.** The test walks the cast spell's sub-ability chain and passes on the first targeted entity that matches (Java `TriggerSpellAbilityCastOrCopy.performTest`); a spell that targets nothing never satisfies it. `IsSingleTarget$` needs exactly one distinct target across the chain, so a targetless trigger never satisfies it either.
- **A triggering spell or ability is shared, not copied.** `SpellAbility::trigger_spell_abilities` holds `Arc<SpellAbility>`, as Forge's triggering objects are references, so a trigger that fires on a trigger does not copy the chain beneath it; the setters that recurse into the map (`set_host_card_id`, `apply_text_change` and the rest) go through `Arc::make_mut`, since the map also stands in for Forge's `additionalAbilities`, which Forge copies. The trigger push in `TriggerHandler::process_pending_triggers` gives `SpellAbilityCast` only `spell_ability`, as `MagicStack.add` passes only `SpellAbility`. `zone::magic_stack::stop_infinite_loop` is the head of `MagicStack.add`: once the stack passes 999 entries the game ends in a draw and nothing more is pushed. Every push calls it: triggers, casts and activations, copies, Replicate, CastFrom and Play.
- **An effect acts on every card its ability targets.** `get_target_cards` and `Defined$ Targeted` return `TargetChoices::all_target_cards`, the first target and the rest (`divided_map`), as Java's `getTargetCards` does; reading `target_card` alone taps, pumps or destroys only the first of several targets.
- **A sub-ability that targets keeps only its own targets.** `Defined$ Targeted` and `ParentTarget` on a later sub-ability read the nearest ancestor that targeted something (Forge's `getParentTargetingCard`/`getParentTargetingPlayer`), so the three chain walkers (`stack_resolution.rs`, `effect_resolver.rs`, `replace_moved.rs`) carry the last non-empty target forward and hand it only to a sub-ability without `ValidTgts$`. Together as One's `DealDamage` used to hit both its own target and the player its `Draw` targeted. A sub-ability that inherits the target card inherits the parent's other target cards (`divided_map`) with it, so `targetedBy` and `Defined$ Targeted` see all of them. A triggered ability's triggering objects and trigger source live on the root; the stack walker hands them to each sub-ability that has none, as Forge reads them through `getRootAbility()`.
- **A copy of a spell gets its own host card, controlled by the copier.** `card_factory::copy_spell_ability_and_possibly_host` mirrors `CardFactory.copySpellAbilityAndPossiblyHost`: unless the copy effect has `UseOriginalHost$`, the host is a new card built from the original (`copied_permanent` set), put on the stack and remembered for `RememberNewCard$`. The copy and each of its sub-abilities get a new `SpellAbility::id` from the game's stack, as `SpellAbility.copy` gives them (`card_factory::copy_spell_ability`). A copy takes the fizzle check like any spell (`MagicStack.hasFizzled`); a permanent copy resolves down the normal permanent path and becomes a token, and a non-permanent host ceases to exist once it resolves or fizzles (`cease_to_exist_copied_spell`). While copies kept the original card, whatever an effect did to "the copy" (Choreographed Sparks' haste and sacrifice) landed on the original, and a copy never fizzled. Replicate (`cast_spell.rs`) still copies without a new host. A copy keeps the original's targets unless the copy effect has `MayChooseTarget$` (every Replicate copy counts as having it, as Forge's Replicate trigger does): then `SpellAbility::setup_new_targets` asks the copier's `PlayerAgent::choose_new_targets_for` once per targeting node, as `setupNewTargets` asks `chooseNewTargetsFor`, and restores the old targets when it answers `false`. `false` is the trait default and what Forge's AI and the harness's `DeterministicController` answer; the interactive agent opens a cancellable target prompt, and cancelling keeps the old targets. A copy of a triggered ability keeps its `Cost$` and pays it as it resolves (`WrappedAbility.resolve`), and under `mirror_forge_bugs` keeps the original trigger's optional decider, as `CardFactory.getCopiedTriggeredAbility` passes it to the new `WrappedAbility`: Forge asks the original's controller whether the copier's optional copy happens.
- **`SpellAbility::id` is numbered per game, by the `MagicStack`.** Java draws every id from one counter for the whole JVM (`SpellAbility.maxId`; `resetIdCounter` exists for parity isolation and nothing calls it). A process-wide counter here made a `StaticEffect$` effect card's name, `Static Effect #<cause id>`, depend on how many games the process had played before, so a game played in a batch ended in a different state from the same game played alone (PG-140). The factory, `new_simple`, the vanilla and permanent spells and a non-LKI `copy_with_host_*` leave the id 0, and `MagicStack::push`, `begin_pending_cast` and `complete_pending_cast` number each node of the chain that has none (`number_spell_abilities`); `copy_spell_ability` takes its copy's ids from the stack. The id is read only once an ability is on the stack (`setup_static_effect`, `get_instance_matching_spell_ability_id`), so code that hands a copy of an ability to a trigger before pushing it numbers the ability first, as the trigger handler, CastFrom and Play do. Without that, `Defined$ TriggeredSpellAbility` holds id 0 and matches no stack entry (Speedball, New Warrior's ChangeTargets).
- **ChangeTargets edits the target spell's stack entry in place.** `change_targets_effect.rs` mirrors `ChangeTargetsEffect.resolve`: it finds each target spell's entry (a `Defined$` spell through `MagicStack::get_instance_matching_spell_ability_id`, which matches `SpellAbility::id`), walks its sub-ability chain and either moves every targeting node to the `DefinedMagnet$` card when `SpellAbility::can_target` allows it, replaces the one target the chooser picks (`ChangeSingleTarget$`, `PlayerAgent::choose_target`), or asks `choose_new_targets_for` with `optional` false. Each object the spell did not target before gets `BecomesTarget`, and `BecomesTargetOnce` fires once. `RandomTarget$` is still a stub that draws one RNG value and changes nothing, and `TargetRestriction$` is not passed to the agent.
- **Clone's `AddSVars$`, `AddTriggers$`, `AddAbilities$` and `AddStaticAbilities$` read the host's SVars as they were before the copy.** Java's `CardFactory.getCloneStates` takes `origSVars` from the cloning ability's host first, so a card copying itself (Vesuvan Shapeshifter, Sakashima the Impostor) still finds the SVars the copy replaces. `clone_effect.rs` adds them before it sets the base counts and the changed-traits baseline, so they are the copy's own traits and the layer pass keeps them. Both copy paths take the copiable values from one place, `card_factory::get_clone_states` (Java `getCloneStates`): CopyPermanent's `copy_permanent_effect::get_proto_type` builds its token from it, and `clone_effect.rs` copies it onto the target through `card_copy_service::copy_copiable_characteristics`. It reads the printed characteristics as the copy effects left them, not what other effects changed: power, toughness, color and type line from the Animate snapshot or the changed-characteristics baseline first (a copy of a creature under Genemorph Imago's landfall is not 6/6), and keywords, triggers, replacement effects and static abilities from the changed-traits baseline (`Card::copiable_keywords`, `copiable_triggers`, `copiable_replacement_effects`, `copiable_static_abilities`), so a copy of a Ravenhill Flock under Retro-Mutation has flying; activated abilities are parsed afresh from the printed ability lines. A face-down original gives the face-down characteristics with no name and no turn-face-up ability. It copies an Adventure or Omen (`Secondary`) or Prepare (`PreparedSpell`) state, and a transforming original's other face only for a CopyPermanent, CopySpellAbility or ReplaceToken cause, keeping the current face, so a token copy of Dowsing Device can transform and the token a copied Jadzi, Steward of Fate spell becomes enters prepared; a copied permanent spell that resolves into a token keeps the face its copy was given (`resolve_copied_permanent_as_token`). `get_proto_type` still reads none of the four `Add*$` parameters (Norin and Feldon, Delina, Wild Mage, Hofri Ghostforge), and each path applies its own other cause parameters.
- **Minimize SVar parsing — this is critical.** SVar resolution is late-bound by spec (`docs/forge-dsl-semantics.md` §5.2). Resolve SVars at the call site, lazily, and only for the SVar the engine actually needs. Do not eagerly walk the SVar graph at card construction or ability registration time. Do not pre-expand sub-ability chains into IR before they are reached. Do not re-parse the same SVar string on every reference — parse once, then reuse the parsed form. Aggressive eager parsing inflates load time, breaks the lazy semantics the spec relies on, and produces stale IR when card state changes (transform, copy, exile) alter the available SVars per invariant §10.7.

## Build & test

The Cargo workspace manifest is at the repository root, not `manabrew-rs/Cargo.toml`; run these commands from the root.

```bash
cargo build --workspace
cargo test --workspace
cargo check -pmanabrew-engine
yarn parity <test-name>          # see parity AGENTS.md
parity query --api <Api> --param <Key>   # which cards use it, and is it in the engine; see parity AGENTS.md
```

Any `manabrew-protocol` or `manabrew-relay-protocol` type change needs three regens: `yarn gen:types` (ts-rs → `src/protocol/`, gitignored), `yarn build:harness` (Java prompt DTOs, gitignored), and `yarn gen:protocol-docs` (`website/src/generated/protocol-types.json`, **committed** — CI fails the PR if stale).

`yarn gen:types` must remain idempotent because lint and build invoke it repeatedly in the same worktree. The protocol generator recreates `src/protocol/`, and xtask removes `src/api/hubTypes.ts` before ts-rs exports; do not change either path to append to existing generated files.

Run the engine unit tests as CI does, `cargo test --release -p manabrew-engine --lib`. In a debug build `match_waiting_triggers` and `resolve_stack` each take close to 1 MiB of stack, and `game_loop::tests::evoke_keeps_etb_triggers_when_spell_resolves` overflows the 2 MiB test thread (`RUST_MIN_STACK=4194304` also gets it through). It is not a recursion bug.

Known debt (as of 2026-07): `yarn lint:rust` (`cargo clippy --workspace -D warnings`) fails on a cold cache with ~110 pre-existing warnings in `manabrew-engine`, `forge-limited`, and `manabrew-server` (mostly `unused_variables`, `needless_bool`). Warm incremental caches hide them until a dependency edit forces a re-check, so a lint failure in crates your diff never touched is probably this — verify against `main` before assuming your change caused it. The parity regression suite (`regression.json`) likewise has pre-existing failing entries (e.g. `kaalia_regression`, `keyword_advanced`, `starter_*`); baseline on `main` before attributing failures to your change.

## Cardset archive

Every engine entrypoint (Tauri runtime, parity binary, self-hosted node, debugger) mmaps a single rkyv archive at startup: `src-tauri/resources/cardset.rkyv`. It bundles cards, tokens, editions, block data, and `lists/TypeLists.txt`. Path override: `CARDSET_ARCHIVE` env var. The web build has its own content-addressed copy at `public/wasm/cardset.<sha8>.rkyv` (resolved via `public/wasm/cardset.manifest.json`) produced by `yarn build:wasm`.

**Who builds it:**

| Trigger                                                                                                   | Output path                                  |
| --------------------------------------------------------------------------------------------------------- | -------------------------------------------- |
| `cargo build -p manabrew` (Tauri) — runs `src-tauri/build.rs`                                             | `src-tauri/resources/cardset.rkyv`           |
| `cargo run -p forge-cardset-archive --features build --release --bin build-cardset-archive` (manual / CI) | `src-tauri/resources/cardset.rkyv` (default) |
| `yarn build:wasm` — runs the bin then copies into `public/wasm/`                                          | `public/wasm/cardset.<sha8>.rkyv` + manifest |

`src-tauri/build.rs::needs_rebuild` checks both data-dir mtimes _and_ calls `forge_cardset_archive::load_checked()` on the existing file. A schema change in `forge-cardset-archive` (struct field added, reorder, type change) breaks `load_checked`, forcing a rebuild even when the source data is untouched. Without that guard, a stale archive on disk would survive a schema bump and panic at runtime with `pointer out of bounds`.

**CI gotcha:** workflows that build a single non-Tauri crate (`parity`, `self-hosted-node`, etc.) never trigger `src-tauri/build.rs`, so the archive isn't produced. Without an explicit build step they start up and panic with `Cardset archive not found at src-tauri/resources/cardset.rkyv`. All three parity workflows (`parity-self-hosted`, `parity-continuous`, `parity_ripper`) now have a `Build cardset archive` step before invoking the binary. Add the same step to any new workflow or local script that runs engine binaries directly.

**Web deploy gotcha (silent empty editions):** the production web archive is built _inside_ `Dockerfile.web` (not from the gitignored `public/wasm/` copy), which must `COPY` all five sources — `cardsfolder`, `tokenscripts`, **`editions`**, **`blockdata`**, **`lists/TypeLists.txt`** — that `scripts/build-wasm.mjs` passes to the builder. `build_archive_from_sources` hard-errors on a missing `cardsfolder` or `TypeLists.txt`; for `editions`/`blockdata` it silently emits an empty vec, so a build that forgets those dirs still succeeds but ships an archive with zero set data, and every limited draft fails with `unknown set: …` on web while Tauri (which always rebuilds from the full res tree) works. The production web image is built by CI (docker-images.yml) from the tag with submodules checked out, so a forge bump lands in the deployed archive with the next release.

**`TypeRegistry` is primed from the archive, at the point the archive loads.** `TypeRegistry::creature_types()` panics if `TypeRegistry::load` was never called, and the failure is delayed and card-specific — `is_creature_type` returns `false` when unloaded rather than panicking, so most of the engine degrades quietly and only changeling / `ChooseType` / tribal text-change cards blow up. Every entrypoint therefore calls `TypeRegistry::load(archive.type_lists.as_str(), archive.editions.iter().map(|e| e.raw.as_str()))` in the same function that loads the cardset bundle (the edition files add their own `[CreatureTypes]`, as `CardEdition.Reader` does in Java, and a `ChooseType` list that misses them draws a different index): `crates/wasm/src/card_loader.rs`, `self-hosted-node/.../rust_backend.rs`, `src-tauri/src/card_db.rs`, `parity/src/runner.rs`. Do **not** reintroduce an `include_str!` of `forge/forge-gui/res/lists/TypeLists.txt` — it makes the crate uncompilable without the submodule checked out, and the web build has no filesystem at runtime anyway. A new entrypoint gets this for free by loading the archive; priming it anywhere else risks running after the first card is used. The same load keeps every `[...Types]` section of `TypeLists.txt` (`TypeRegistry::is_subtype_in`, `is_land_type`): after a layer pass changes a card's types, `staticability/layer.rs` drops the subtypes that no longer fit its card types, as `CardType.sanisfySubtypes` does, and skips that step while the sections are not loaded (unit tests).

**DFC name lookups:** `CardDatabase::get_by_card_name` first tries the full string, then on miss splits at `" // "` and retries with just the front face. Split cards (`"Fire // Ice"`, stored as the full name) hit on the first attempt; Scryfall-style DFC names (`"Fable of the Mirror-Breaker // Reflection of Kiki-Jiki"`) resolve via the fallback. Deck imports that come straight from Scryfall don't need pre-processing for the engine.

**Flavor-name lookups:** a Universes Beyond printing is a `Variant:UniversesWithin:FlavorName:` line on the Universes Within card, not a card of its own, so `"A Most Helpful Weaver"` has to resolve to `Origin of Spider-Man`. Aliases come from two scans at archive load — `extract_flavor_aliases_from_edition_contents` for the edition files and `extract_flavor_aliases_from_card_scripts` for the card scripts. Both are needed because `register_flavor_aliases_for_card` only runs on the eager bulk-parse path, and every engine binary takes the lazy archive path, where nothing parses a card until it is asked for by name. A new alias source needs its own scan here; registering it at parse time is too late for the card that alias names.

## Web Image engine assets

The Forge Web Image build carries its whole asset tree **inside the wasm module** as a build-time resource: `scripts/build-forge-wasm.sh` builds `target/forge-cardset.rkyv` from the submodule's res dirs, frames it with `emit-forge-assets` into `target/forge-assets-framed.txt`, and `forge-harness/build-wasm.sh` embeds it via `-H:IncludeResources` (`FORGE_ASSETS` is mandatory — a module without the resource throws at boot rather than degrading). `WasmMain` streams it into the VFS with no JavaScript boundary crossing, so Forge's lazy card index comes up over every card (measured: ~470 ms unpack, ~500 ms full 33.7k-script index). Keep the bundle **uncompressed**: the Web Image build links no zip library, so a gzipped resource dies in `GZIPInputStream` with an `UnsatisfiedLinkError`.
