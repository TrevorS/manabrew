# Rust engine workspace

This is the Rust port of Forge's Java rules engine. Read the root `/AGENTS.md` first, plus `docs/agents/PARITY_PHILOSOPHY.md`. Most parity work bottoms out here.

## Required reading: the DSL spec

Card scripts are the source of truth for behavior; the engine evaluates them. Before any work that touches abilities, triggers, replacements, static abilities, costs, the stack, SVars, selectors, or layered effects, read:

- **`docs/forge-dsl-semantics.md`** — runtime model: execution pipeline, stack semantics, targeting, cost payment, layer system, SVar resolution, determinism invariants, known CR deviations.
- **`docs/forge-dsl-grammar.md`** — syntax / parsing model. Read this when working on the parser, the IR, or interpreting an unfamiliar param.

When you write or change engine logic, write IRs and resolution code that mirror the semantics in the spec exactly. If your implementation diverges from the spec, either the implementation is wrong or the spec needs updating — don't silently drift.

## Conventions

- **Mirror Java exactly.** See `docs/agents/PARITY_PHILOSOPHY.md`.
- **One Forge concept per file.** New effects, triggers, replacements, statics, keywords each get their own file named after the Java class, registered in their module's `mod.rs`.
- **`Game` owns everything.** All mutation flows through `&mut Game`. No interior mutability, no shared references.
- **Engine hash collections use the fixed-hasher aliases.** `crate::HashMap` and `crate::HashSet` (`manabrew-engine/src/lib.rs`) wrap the std collections with `DefaultHasher`, so iteration order is the same on every run of the same seed. `manabrew-engine/clippy.toml` rejects `std::collections::HashMap`, `HashSet`, `RandomState`, and `rand::thread_rng`. Where iteration order reaches game logic, use `IndexMap`/`IndexSet`.
- **Crate-wide `#![allow(...)]`s in `lib.rs` are intentional.** They document parity trade-offs.
- **A trigger pushed onto a built card must raise `base_trigger_count`.** The layer reset in `staticability/layer.rs` truncates `card.triggers` to `base_trigger_count + pump_trigger_count` on every pass, so a trigger added to an effect card after construction vanishes on the first zone move unless the count covers it. `effect_effect.rs` and `player/player_factory_util.rs::add_trigger` both set it; do the same in any new code that builds an effect card.
- **A keyword that changes a card's types does it inline in the layer pass, not through a generated static.** `keyword_gen.rs` makes triggers and abilities but no static abilities, and `StaticAbility::remove_type` is parsed from `RemoveType$` and then never read, so a `RemoveType$` written into a card script is silently a no-op. Keyword-derived type and restriction changes live in the "Keyword-derived restrictions" block of `staticability/layer.rs` (Unleash's can't-block, Impending's `RemoveType$ Creature`), which runs after the per-pass reset so it recomputes every pass and reverts on its own. Anything there that drops a card type must call `sanitize_subtypes` itself, as the `type_changed` loop at the end of the pass does — that loop only covers targets the static effects touched, so an inline change skips it and leaves creature subtypes on a card that is no longer a creature.
- **A face-down permanent has a face-down state.** `Card::set_original_state_as_face_down` (Forge: `setOriginalStateAsFaceDown` + `CardUtil.getFaceDownCharacteristic`) saves the printed characteristics in `face_down_state` and leaves a colourless 2/2 `Creature` with no cost and no abilities; `turn_face_up` restores them, and every path that turns a card up or moves it between zones goes through `turn_face_up`. `card_name` is kept, so name lookups still work; the parity snapshot and `FmtCtx::card` blank it. The face-down cast (Morph, Megamorph, Disguise) applies it before the permanent enters, as `abilityCastFaceDown.resolve` does, so enters-the-battlefield replacements see the face-down card. Manifest, Manifest Dread and Cloak apply it before the card moves, as `Card.manifest` and `Card.cloak` do; Cloak's Ward:2 is an intrinsic keyword of the face-down state, not a pump keyword that cleanup removes. A manifested or cloaked creature card gets a `Mode$ TurnFaceUp | ManifestUp$ True` (or `CloakUp$`) ability for its mana cost from `card_factory_util::ability_turn_face_up` (Forge: `CardState.getManifestUp`), pushed before the move as the morph cast pushes its own; cost reductions for turning face up (`ValidSpell$ Static.isTurnFaceUp`) are not applied yet. Turning face up restores the card first and runs the `TurnFaceUp` replacement after, behind a `cant_happen_check` (Forge: `Card.turnFaceUp`), and its `ReplaceWith$` ability runs through `replace_moved::execute_replace_with`.
- **A token's edition follows `TokenInfo.getProtoType`, and its art pick draws from the game RNG.** `EffectContext::sync_token_art_rng` starts from the ability's original host (else its host), follows `TokenFallbackCode`, and pins the script's edition for the rest of the game (`GameState::token_edition_pins`). An edition without the token falls back to the first edition, in code order, that has it (`TokenDb.getTokenFromEditions`); more than one art variant draws `nextInt(variants)`. The token takes that edition as its set code and an effect card takes its host's, as in Forge; other cards made during the game have no set code and go straight to the fallback.
- **A trigger's player filter goes through `player_property::is_valid`** (Java `Player.isValid`), from `Trigger::matches_optional_valid_player_filter`. The compiled-selector player matcher in `valid_filter.rs` has no game, so it cannot answer `Active`, `NonActive` or any other property that needs one and counts them as matches. A spell-cast trigger reads the caster from `RunParams::activator`, which every `SpellCast` emitter sets, as `MagicStack.add` puts `AbilityKey.Activator`.
- **An attacker that leaves the battlefield stays in `CombatState::attackers`** until `remove_absent_combatants` prunes it after the declare-blockers priority round. Code that reads attackers in the middle of a step checks the card's zone, as the Sneak offer in `playability.rs` does; a creature returned to hand by Sneak's cost is still found by `get_defender_by_attacker` when the Sneak spell resolves.
- **`ChangesZoneAll` fires from a `CardZoneTable`.** Moves record into `GameState::pending_change_zone_table` while one is open. Stack resolution, a permanent spell entering (`PermanentEffect`) and each state-based-action pass (`state_based_actions_pass`, up to nine passes as in `GameAction.checkStateEffects`) open one and end with `trigger_changes_zone_all`. A move outside those needs its own table, or "one or more" triggers never see it.
- **Damage to a player loses life through `simultaneous_damage`.** `player_deal_damage` adds the life lost to `PlayerState::simultaneous_damage`; `GameState::lose_life_simultaneously` (the tail of Forge's `GameAction.dealDamage`) drains it and fires `LifeLost` per player and then `LifeLostAll`. It runs after every effect in `resolve_effect_once`, in `fire_combat_damage_triggers`, and at the `DamageYou` cost sites. A new damage path outside those three needs its own call.
- **A card that changes zones is a new object; nothing about the old one may follow it.** Forge makes a new `Card` and compares objects with `equalsWithGameTimestamp`; this engine keeps one `Card` per id, so every piece of per-object state needs an explicit reset in `GameState::move_card`. What is reset today when a permanent leaves the battlefield: the changed-characteristics baseline (`capture_changed_characteristics_baseline_if_needed` saves type line, power/toughness, keywords and the base trigger count; Earthbend and a `Duration$ Permanent` Animate use it, and `Card::add_lasting_trigger` is the way to grant a trigger for the life of the object), the whole until-end-of-turn animate snapshot, `imprinted_cards`, `exiled_cards` (the "exiled with" list, Java `Card.exiledCards`, kept apart from the imprinted list as in Forge), the transformed face, and `cast_from`. `cast_from` is set as the cast moves the card to the stack, before its costs (Forge: `GameAction.changeZone`), and cleared when the card leaves the stack for anywhere but the battlefield. `cast_with_flashback` and `cast_with_harmonize` are written on every cast, and the warp mark goes when the card leaves exile. A delayed trigger that must follow one object and not the card sets `DelayedTrigger::target_card_zone_timestamp` (Earthbend's return triggers); it is compared with the card's zone timestamp while it is still on the battlefield and with `Card::lki_zone_timestamp` after the move. New per-object state needs the same treatment, or it shows up as a late-game divergence after a bounce.
- **An Effect's `Duration$` goes through `spell_ability_effect::add_until_command` (Java `SpellAbilityEffect.addUntilCommand`) when it ends at a turn boundary.** `UntilYourNextTurn` queues `PhaseCommand::ExileEffect` on `GameState::cleanup` for the controller, and `UntilTheEndOfYourNextTurn` on `GameState::end_of_turn` (`register_until_end` on the controller's own turn, `add_until_end` otherwise), which `cleanup_damage_and_eot` runs as Java's CLEANUP does. The host-leaves durations use the `temp_effect_host` flags, and so do `AsLongAsControl`, `AsLongAsInPlay` and `UntilLoseControlOfHost` for an Effect (their change-of-control and phase-out ends, Java `addChangeControllerCommand` and `addPhaseOutCommand`, are not ported). `UntilEndOfCombat` goes on `GameState::end_of_combat`, `UntilNextEndStep` on `end_of_turn` with `add_at` (no controller, the next end step whoever's turn it is) and `UntilYourNextEndStep` on `end_of_turn` with `add_until` for the controller. Every other duration still ends at the end of the turn: port it into `add_until_command` with the Java `Phase` it names, reading the branch out of `SpellAbilityEffect.addUntilCommand`. Note that a probe rarely observes a duration fix — the effect has to outlive the turn it was made in and then matter — so audit the parse and the phase hook rather than expecting card movement. A Pump's keywords with either next-turn duration go there too, as `PhaseCommand::RemoveKeyword`; its power and toughness still end at the end of the turn. A goad lasts `UntilYourNextTurn` unless the Goad names another `Duration$`, and ends through `PhaseCommand::RemoveGoad`.
- **`BecomesTarget` fires when the spell or ability reaches the stack, for every target in the chain.** `emit_becomes_target_triggers` runs from `emit_post_stack_spell_ability_triggers` for spells and activated abilities alike, walks the sub-abilities (a Charm keeps its targets on the chosen mode) and fires `BecomesTargetOnce` once. Do not fire it when targets are chosen: a cast cancelled at its cost must not trigger anything.
- **Two agent callbacks mirror `PlayerController` methods whose human version answers without a prompt.** `order_move_to_zone_list` carries the destination zone (the interactive agent returns the cards unchanged for Hand and Graveyard, as `PlayerControllerHuman` does with default preferences), and `choose_cards_to_discard_unless_type` defaults to `choose_discard`. `GameNotification::SpellPaymentFailed` is sent from every cast rollback from the cost adjustment on, and not for a Charm choice, an announcement or targeting; the parity harness uses it to drop the card from the action space for the turn, as `HarnessPlayPlumbing` does.
- **Castability checks mirror `ComputerUtilMana`, quirks included.** A `RestrictValid$` mana source is tested against the spell being paid for only. For a Secondary-face cast (Adventure, Omen) the probe tests `Spell.<Type>` against the card as it sits in hand, because Forge asks `sa.getHostCard().hasProperty`; the payment, with the card on the stack, uses the face being cast. A mana ability whose `PayLife` would leave the player below 1 is not counted ("don't kill yourself"). A `Waterbend` cost counts mana only, not the creatures and artifacts it could tap, because `calculateManaCost` clears `maxWaterbend` in test mode when the payer's controller is not the AI (`cost_waterbend::can_pay`). A Waterbend arriving through `Mode$ RaiseCost` has to be added to the required mana by hand (`playability::raise_mana_from_cost`): `mana_from_cost` sums only `CostPart::Mana`, and `can_pay_ignoring_mana_for_spell` answers true for a Waterbend, so a raise cost carrying one would otherwise be free on both paths. Convoke and Improvise are applied before any mana source, each untapped creature or artifact in name order paying one shard of its colour (`computer_util_mana::adjust_cost_by_convoke_or_improvise`, the harness's probing `chooseCardsForConvokeOrImprovise`); the payment itself convokes after the mana sources. Mana from `TapsForMana` triggers (Mana Flare, Lavaleaper) is predicted by `add_taps_for_mana_trigger_mana_impl` in both the probe and the auto-pay, as `ComputerUtilMana.predictMana` does: only triggers that could run (`getActiveTrigger`: zone, `IsPresent$`, limit, mode test), a `Mana` trigger adding its `Produced$`, a `ManaReflected` trigger one of the mana the land made. The graveyard and exile cast checks go through `available_mana_for_spell_card` so that they apply the same restrictions as the hand check. `GameState::action_space_mana_probe` picks the spell probe: `AutoPay` (the default, and the app's) simulates the engine's own payment; `ComputerUtilMana` (the parity default) ports `ComputerUtilMana.canPayManaCost` in test mode (Java's source order, `sortManaAbilities`, `chooseManaAbility`, `payMultipleMana`), which refuses some payable costs as Forge does, and it turns off the source-level fallback in `playability.rs`.
- **An activated ability's mana cost is adjusted like Java's `CostAdjustment.adjust`.** `cost_adjustment::adjust_ability_mana_cost` applies the ability's `ReduceCost$`/`ReduceAmount$`, PowerUp (the host's mana cost, if it entered this turn) and the `ReduceCost`/`RaiseCost` statics whose `Type$ Ability` or `ValidSpell$ Activated.<property>` accepts the ability, in both the activation check and the payment (`GameLoop::adjusted_activation_cost`). A mana part that comes to zero is not paid, so no `pay_mana_cost` callback runs, as in the harness.
- **A `MayPlay$` grant with `MayPlayAltManaCost$` adds a copy of each hand option that pays that cost instead of the mana cost** (Java `GameActionUtil.getMayPlaySpellOptions`): `PlayCardMode::MayPlay(base)`, with `base` the option it copies (`None` for the spell, `Some(Morph)` for the face-down cast) and `alt_cost_index` the grant in `static_ability_continuous::may_play_alt_costs` order. The cost is parsed as a full `Cost` (`CollectEvidence<10>`, `PayLife<...>`) and paid through the static-alternative path. A grant made with `MayPlayDontGrantZonePermissions$` casts from hand only; the graveyard and exile loops ask `grants_zone_permissions`. Those loops still offer `Normal` and read the first grant's cost as a mana cost at cast time.
- **One card's simultaneous triggers follow Forge's trigger ids, and those depend on how the card object was built.** The parity harness orders them by host timestamp and then trigger id. On every zone change `CardCopyService.copyCard` rebuilds a card that has a paper card from its script: `T:` triggers first, keyword triggers after. A keyword trigger (Evoke's sacrifice) therefore has the higher id, is pushed after the card's own enters triggers and resolves first. A token or a copied permanent goes through `copyStats` (`CardState.copyFrom`), which copies the keywords first. `register_evoke_sacrifice_triggers` sets `DelayedTrigger::sort_after_active` from that rule; a new keyword trigger modelled as a delayed trigger needs the same decision.
- **An ability that runs inside a Moved replacement gets the game runtime.** `move_card_internal` takes the `ReplacementRuntime`, so a `ReplaceWith$` chain on a permanent entering the battlefield (an enters-as-a-copy Clone, its `ImmediateTrigger`) registers delayed triggers on the real `TriggerHandler` and draws from the game RNG. State-based deaths get it through `SbaReplacementParts` (`GameLoop::sba_runtime`), so Head of the Hunt's `ImmediateTrigger` makes its Wolf. `GameState::move_card` and `move_card_with_agents` have no runtime and still fall back to a local handler; move through `EffectContext::move_card` or `GameLoop::move_card_with_runtime` wherever one is in reach. `ReplaceWith$` always names an SVar, even `ReplaceWith$ Exile`; only the engine's own `NewDestination$` redirects by zone name. A result other than `NotReplaced` or `Updated` ends the move, as in `GameAction.changeZone`, because the replacement's ability already moved the card; a new Moved call site must check the result too. A move with a trigger handler also registers the card's triggers in its new zone, as `GameAction.changeZone` does; after a move without one, an effect card's `Static$` trigger stays inactive until the next `reset_active_triggers`.
- **A zone's card list runs oldest first in Rust and, for the moves the probes see, newest first in Forge.** `moveTo(ZoneType, …)` inserts at index 0 and a library's top is its last Rust element. Name-sorted choices do not care, but a random pick does: `change_zone_effect::search::resolve_random_selection` orders the candidates player by player, newest first, and draws one `nextInt(size)` per pick as `Aggregates.random` does.
- **A `HIDDEN ` keyword keeps its prefix in the keyword sets, and `has_keyword` matches it without the prefix** (Forge: `addHiddenExtrinsicKeywords` stores `kw.substring(7)`, `Card.hasKeyword` checks the hidden list). The parity snapshot leaves `HIDDEN` entries out, as Forge's keyword list does. A `Duration$ Permanent` Pump puts its keywords in the changed-keyword set, which cleanup does not clear; the untap step removes `This card doesn't untap during your next untap step.` from the active player's permanents after untapping, as `Untap.doUntap` does.
- **`SpellAbility::description` is empty for abilities built from a script.** Java's `AbilityFactory` sets it from `SpellDescription$`; the port does not, and `ir.sp_desc_text` reads `SpDesc$`, which no script has, so `rebuilt_description` falls back to the ability text. Where Forge reads a sub-ability's `getDescription()` as data, read `ir.spell_description_text`, as `choose_generic_effect.rs` does for `SetChosenMode$` (the `ChosenMode<X>` card property).
- **`Execute$` abilities and sub-abilities are looked up by name on the host when they resolve; Forge builds them with the ability.** Anything that swaps a host's SVars in the middle of its own chain has to keep the host's SVars as a fallback, as `clone_effect.rs` does when a card clones onto itself. A copy that leaves the battlefield keeps its copied SVars behind the restored ones (`Card::restore_clone_snapshot_keeping_svars`), so a trigger it already put on the stack still finds its sub-abilities. `ImmediateTrigger` and `DelayedTrigger` remember `RememberObjects$` on the trigger, resolved through `get_defined_entities`, never on the host. A trigger granted to another card (Animate's `Triggers$`) therefore has to be given the whole chain, not just the `Execute$` SVar: `animate_effect::copy_execute_chain_svars` follows each `SubAbility$` from the source's SVars onto the target, because Forge attaches the built sub-abilities to the trigger and this port looks them up by name at resolution. Copying only the first name resolved the trigger and silently dropped everything after it — Fake Your Own Death returned the creature and never made its Treasure.
- **`Defined$ Valid <filter>` resolves in `ability_utils::get_defined_valid_cards`** (the `Valid` branch of Java `AbilityUtils.getDefinedCards`): `Valid ` searches every battlefield, `ValidAll ` every zone, and `Valid<Zone> ` that zone for every player, filtered with the ability's context. `get_defined_cards` and the ability-aware `resolve_defined_cards_for_sa` both go through it; an effect that parses `Valid` itself (`clone_effect.rs`, `airbend_effect.rs`) predates it.
- **An effect that acts on players and cards picks them with `spell_ability_effect::get_target_entities`** (Java `getTargetEntities`): the targets when the ability targets, otherwise the `Defined$` cards and players. Only player-capable refs (`You`, `Targeted`, `TriggeredTarget`, `Remembered`, ...) reach `resolve_defined_players_with_sa`, because that resolver answers any value it does not know with the activator; asking it about `Self` is how `DealDamage | Defined$ Self` used to damage its controller. DealDamage also takes its sources from `DamageSource$` and stores excess damage to cards in `ExcessSVar$` on the host.
- **A trigger's condition is checked twice: when it fires and again when it resolves.** `stack_resolution::trigger_requirements_still_met` (Java `WrappedAbility.resolve`) re-runs `Trigger::requirements_check` before an `is_trigger` entry resolves and does nothing when it now fails, skipping that only for an `Always` trigger or one with `NoResolvingCheck$`. Java's second half, `meetsRequirementsOnTriggeredObjects`, is not ported: it needs the `RunParams` the trigger fired with, and the stack entry does not carry them.
- **A later sub-ability may not repeat an earlier one's target when it has `TargetUnique$`.** Java reads the ancestors' targets back up the parent chain in `getUniqueTargets`; there is no parent link here, so `SpellAbility::setup_targets` collects them going down and writes `SpellAbility::unique_targets` on each node before it picks. The rest of the `TargetRestrictions` family (`TargetsForEachPlayer`, `TargetsWithSameController`, `TargetsWithoutSameCreatureType`, ...) is still unported: those compare a candidate against the _same_ node's already-chosen targets, which needs incremental per-target choice, and this port picks a node's targets in one batch call.
- **A `SpellCast` trigger with `TargetsValid$` only sees spells that target a matching entity.** The test walks the cast spell's sub-ability chain and passes on the first targeted entity that matches (Java `TriggerSpellAbilityCastOrCopy.performTest`); a spell that targets nothing never satisfies it.
- **A sub-ability that targets keeps only its own targets.** `Defined$ Targeted` and `ParentTarget` on a later sub-ability read the nearest ancestor that targeted something (Forge's `getParentTargetingCard`/`getParentTargetingPlayer`), so the three chain walkers (`stack_resolution.rs`, `effect_resolver.rs`, `replace_moved.rs`) carry the last non-empty target forward and hand it only to a sub-ability without `ValidTgts$`. Together as One's `DealDamage` used to hit both its own target and the player its `Draw` targeted. A triggered ability's triggering objects and trigger source live on the root; the stack walker hands them to each sub-ability that has none, as Forge reads them through `getRootAbility()`.
- **Minimize SVar parsing — this is critical.** SVar resolution is late-bound by spec (`docs/forge-dsl-semantics.md` §5.2). Resolve SVars at the call site, lazily, and only for the SVar the engine actually needs. Do not eagerly walk the SVar graph at card construction or ability registration time. Do not pre-expand sub-ability chains into IR before they are reached. Do not re-parse the same SVar string on every reference — parse once, then reuse the parsed form. Aggressive eager parsing inflates load time, breaks the lazy semantics the spec relies on, and produces stale IR when card state changes (transform, copy, exile) alter the available SVars per invariant §10.7.

## Build & test

```bash
cargo build --workspace
cargo test --workspace
cargo check -pmanabrew-engine
yarn parity <test-name>          # see parity AGENTS.md
parity query --api <Api> --param <Key>   # which cards use it, and is it in the engine; see parity AGENTS.md
```

Any `manabrew-protocol` or `manabrew-relay-protocol` type change needs three regens: `yarn gen:types` (ts-rs → `src/protocol/`, gitignored), `yarn build:harness` (Java prompt DTOs, gitignored), and `yarn gen:protocol-docs` (`website/src/generated/protocol-types.json`, **committed** — CI fails the PR if stale).

`yarn gen:types` must remain idempotent because lint and build invoke it repeatedly in the same worktree. The protocol generator recreates `src/protocol/`, and xtask removes `src/api/hubTypes.ts` before ts-rs exports; do not change either path to append to existing generated files.

Run the engine unit tests as CI does, `cargo test --release -p manabrew-engine --lib`. In a debug build `match_waiting_triggers` and `resolve_stack` each take close to 1 MiB of stack, and `game_loop::tests::evoke_keeps_etb_triggers_when_spell_resolves` overflows the 2 MiB test thread (`RUST_MIN_STACK=4194304` also gets it through). It is not a recursion bug.

Known debt (as of 2026-07): `yarn lint:rust` (`cargo clippy --workspace -D warnings`) fails on a cold cache with ~110 pre-existing warnings in `manabrew-engine`, `forge-limited`, and `manabrew-server` (mostly `unused_variables`, `needless_bool`). Warm incremental caches hide them until a dependency edit forces a re-check, so a lint failure in crates your diff never touched is probably this — verify against `main` before assuming your change caused it. The parity regression suite (`regression.json`) likewise has pre-existing failing entries (e.g. `kaalia_regression`, `keyword_advanced`, `starter_*`); baseline on `main` before attributing failures to your change.

## Cardset archive

Every engine entrypoint (Tauri runtime, parity binary, self-hosted node, debugger) mmaps a single rkyv archive at startup: `src-tauri/resources/cardset.rkyv`. It bundles cards, tokens, editions, block data, and `lists/TypeLists.txt`. Path override: `CARDSET_ARCHIVE` env var. The web build has its own content-addressed copy at `public/wasm/cardset.<sha8>.rkyv` (resolved via `public/wasm/cardset.manifest.json`) produced by `yarn build:wasm`.

**Who builds it:**

| Trigger                                                                                                   | Output path                                  |
| --------------------------------------------------------------------------------------------------------- | -------------------------------------------- |
| `cargo build -p manabrew` (Tauri) — runs `src-tauri/build.rs`                                             | `src-tauri/resources/cardset.rkyv`           |
| `cargo run -p forge-cardset-archive --features build --release --bin build-cardset-archive` (manual / CI) | `src-tauri/resources/cardset.rkyv` (default) |
| `yarn build:wasm` — runs the bin then copies into `public/wasm/`                                          | `public/wasm/cardset.<sha8>.rkyv` + manifest |

`src-tauri/build.rs::needs_rebuild` checks both data-dir mtimes _and_ calls `forge_cardset_archive::load_checked()` on the existing file. A schema change in `forge-cardset-archive` (struct field added, reorder, type change) breaks `load_checked`, forcing a rebuild even when the source data is untouched. Without that guard, a stale archive on disk would survive a schema bump and panic at runtime with `pointer out of bounds`.

**CI gotcha:** workflows that build a single non-Tauri crate (`parity`, `self-hosted-node`, etc.) never trigger `src-tauri/build.rs`, so the archive isn't produced. Without an explicit build step they start up and panic with `Cardset archive not found at src-tauri/resources/cardset.rkyv`. All three parity workflows (`parity-self-hosted`, `parity-continuous`, `parity_ripper`) now have a `Build cardset archive` step before invoking the binary. Add the same step to any new workflow or local script that runs engine binaries directly.

**Web deploy gotcha (silent empty editions):** the production web archive is built _inside_ `Dockerfile.web` (not from the gitignored `public/wasm/` copy), which must `COPY` all five sources — `cardsfolder`, `tokenscripts`, **`editions`**, **`blockdata`**, **`lists/TypeLists.txt`** — that `scripts/build-wasm.mjs` passes to the builder. `build_archive_from_sources` hard-errors on a missing `cardsfolder` or `TypeLists.txt`; for `editions`/`blockdata` it silently emits an empty vec, so a build that forgets those dirs still succeeds but ships an archive with zero set data, and every limited draft fails with `unknown set: …` on web while Tauri (which always rebuilds from the full res tree) works. The production web image is built by CI (docker-images.yml) from the tag with submodules checked out, so a forge bump lands in the deployed archive with the next release.

**`TypeRegistry` is primed from the archive, at the point the archive loads.** `TypeRegistry::creature_types()` panics if `TypeRegistry::load` was never called, and the failure is delayed and card-specific — `is_creature_type` returns `false` when unloaded rather than panicking, so most of the engine degrades quietly and only changeling / `ChooseType` / tribal text-change cards blow up. Every entrypoint therefore calls `TypeRegistry::load(archive.type_lists.as_str(), archive.editions.iter().map(|e| e.raw.as_str()))` in the same function that loads the cardset bundle (the edition files add their own `[CreatureTypes]`, as `CardEdition.Reader` does in Java, and a `ChooseType` list that misses them draws a different index): `crates/wasm/src/card_loader.rs`, `self-hosted-node/.../rust_backend.rs`, `src-tauri/src/card_db.rs`, `parity/src/runner.rs`. Do **not** reintroduce an `include_str!` of `forge/forge-gui/res/lists/TypeLists.txt` — it makes the crate uncompilable without the submodule checked out, and the web build has no filesystem at runtime anyway. A new entrypoint gets this for free by loading the archive; priming it anywhere else risks running after the first card is used. The same load keeps every `[...Types]` section of `TypeLists.txt` (`TypeRegistry::is_subtype_in`, `is_land_type`): after a layer pass changes a card's types, `staticability/layer.rs` drops the subtypes that no longer fit its card types, as `CardType.sanisfySubtypes` does, and skips that step while the sections are not loaded (unit tests).

**DFC name lookups:** `CardDatabase::get_by_card_name` first tries the full string, then on miss splits at `" // "` and retries with just the front face. Split cards (`"Fire // Ice"`, stored as the full name) hit on the first attempt; Scryfall-style DFC names (`"Fable of the Mirror-Breaker // Reflection of Kiki-Jiki"`) resolve via the fallback. Deck imports that come straight from Scryfall don't need pre-processing for the engine.

**Flavor-name lookups:** a Universes Beyond printing is a `Variant:UniversesWithin:FlavorName:` line on the Universes Within card, not a card of its own, so `"A Most Helpful Weaver"` has to resolve to `Origin of Spider-Man`. Aliases come from two scans at archive load — `extract_flavor_aliases_from_edition_contents` for the edition files and `extract_flavor_aliases_from_card_scripts` for the card scripts. Both are needed because `register_flavor_aliases_for_card` only runs on the eager bulk-parse path, and every engine binary takes the lazy archive path, where nothing parses a card until it is asked for by name. A new alias source needs its own scan here; registering it at parse time is too late for the card that alias names.

## Web Image engine assets

The Forge Web Image build carries its whole asset tree **inside the wasm module** as a build-time resource: `scripts/build-forge-wasm.sh` builds `target/forge-cardset.rkyv` from the submodule's res dirs, frames it with `emit-forge-assets` into `target/forge-assets-framed.txt`, and `forge-harness/build-wasm.sh` embeds it via `-H:IncludeResources` (`FORGE_ASSETS` is mandatory — a module without the resource throws at boot rather than degrading). `WasmMain` streams it into the VFS with no JavaScript boundary crossing, so Forge's lazy card index comes up over every card (measured: ~470 ms unpack, ~500 ms full 33.7k-script index). Keep the bundle **uncompressed**: the Web Image build links no zip library, so a gzipped resource dies in `GZIPInputStream` with an `UnsatisfiedLinkError`.
